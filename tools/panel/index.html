一、[DEC] 是什么

DEC = Decision（决策）。它是我们给代码里所有"做判断"的地方加的统一标记。 普通日志里混着 cv_bridge、BPU、launch 的噪声，加了 [DEC] 之后 就能一键过滤出"车在这一刻做了什么决定"。

格式统一为：[DEC] 区域 事件 键=值 键=值，同时会汇总成 events.csv， 一行一个事件，带相对时间，可以和录像时间轴对齐。

二、常见决策事件

事件含义对应规则
yellow stop_begin看到黄线，开始刹车停车线必须完全停住
yellow temp_stop停 N 秒后继续—
yellow final_stop第 4 根黄线，永久停（完赛）终点
state change巡线状态切换：tracking / lost / yellow_line_detected—
red avoid_on检测到路锥/红线，开始绕行（side=左还是右）碰撞 +10s
digit turn识别到数字，按数值决定转向Bonus −5s/个
mux change速度仲裁切换：follower → detection → stop—
safety deadman_on上游全静默，兜底发零速救车防失控
param effective节点启动时真正加载的参数值判断改参数是否生效
panel param_write面板把参数写进了 YAML—

三、比赛指标怎么算

指标规则
基本计时得分从起跑到完全停住的总秒数，越短越好
停车线未停稳+15 s / 次（最高频扣分）
闯入红色禁行区+30 s / 次
碰撞红色路锥+10 s / 次
压线+15 s / 次；持续压线按每秒 1 次算
Bonus 数字完全覆盖数字即得分，每个 −5 s

综合得分 = 时间 + 罚时 − 5 × Bonus，分数越低排名越高。 所以：一次违规 ≈ 3~6 个 Bonus 的收益，稳比快重要。

五、为什么改了参数车没变

代码里大部分参数是启动时读一次存进变量的，运行中改 YAML 不会回头重读。 所以正确流程是：改参数 → 保存 → 重启巡线节点。点「保存并重启巡线」会自动做这两步， 重启后在「生效参数」卡片和日志 [DEC] param effective 行里能看到新值。
